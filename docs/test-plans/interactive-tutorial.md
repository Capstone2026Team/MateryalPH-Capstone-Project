# Interactive tutorials

The Vendor portal and Buyer app introduce the real interface after authentication and required account/setup gates. Vendor welcome, verification, activation and Buyer location setup retain their existing behavior. Tutorials never submit an inquiry, create an order, reserve stock, change a listing or accept terms.

## Experience

- The Vendor introduction appears on the first eligible dashboard visit without an `overview` acknowledgment, then continues into the detailed Dashboard guide. Buyer retains its first eligible home introduction. Existing accounts without tutorial history receive this introduction once after rollout too.
- Back and Next move between highlights; Finish records `COMPLETED`. Skip, close, Escape/browser dialog cancellation and mobile Back record `SKIPPED`. Both statuses suppress automatic replay. A replay can promote skipped to completed, and never clears completion.
- Vendor Help / tutorial is a searchable, grouped guide library. It includes Dashboard; Orders, Fulfillment, Messages, E-Invoices, Disputes & Appeals and Ratings & Reviews; listings, inventory and Vehicles; Finance overview, commissions, transactions and Xendit remittance; Store Performance and Product Analytics; Team Accounts and Team Tracking; Store Profile, account/security, notifications and private support. Restricted/disabled destinations are omitted. Record editors, statement details, cases, reviews, individual product analytics and current setup steps are guided only after the user opens an actual page/record.
- The first-login introduction stays compact. The manual complete Vendor tour visits available pages and their chapters. Dashboard covers Overview, Traffic & Volume and Disputes & Quality, including every currently rendered metric, section and graph. Each chapter uses semantic UI headings and curated explanations, so absent role-scoped panels are not invented. Existing section-navigation/save guards remain in effect; a rejected guard stops preparation instead of advancing with incorrect content.
- Tour this page covers the current workspace. The library offers one tour per feature, with no individual section or tab buttons. Each feature has one continuous tour with Next and Back across its tabs and related pages. Finance continues through overview, commission monitoring, transactions and remittance; My Products continues into authorized Inventory. Preparation is cancellable and a page failure has Retry and Close, without reporting successful completion.
- Tutorial copy defines the highlighted feature or measure using the current workflow. Page-specific definitions distinguish repeated labels, such as store-wide Orders confirmed and an employee's attributed confirmations. There is no generic metric, chart, section or field fallback. A step needs an authored definition or the existing static panel-purpose text; unknown labels do not create filler steps.
- Team Tracking automatically opens the first account returned by the authorized member list, retaining a later manual choice across refreshes and filters. Its tutorial waits for initial member selection and introduces shared controls once, then continues through Statistics, Activity history and Role responsibilities. When an authorized successful read confirms no accounts, the tour opens a clearly labeled, separate tutorial demo with a fictional Inventory Staff account, statistics and audit event. Failed, loading and denied reads must not trigger that fallback. Employee names and real audit values never become tutorial copy.
- An empty E-Invoices view opens a separate sample walkthrough covering the queues, preparation, local file selection, draft, review, simulated Send and Buyer return. It reuses the invoice workspace, preparation fields and detail summary. A viewing-only role receives a read-only sample, with no preparation or Send controls. Official invoice numbering, BIR compliance, order amounts and immutable sent versions remain separate from this example.
- Help includes **Practice adding a product** (`catalog.manage`), **Practice adding a vehicle** (`vehicles.manage`), **Practice E-Invoices** and **Practice Team Tracking**, only within authorized available workspaces. Product practice follows the real material, information/pricing, photos and review components. Vehicle practice uses the actual editor, capacity validation and rate calculator. Next validates the required local fields/actions; Back retains practice values; Skip/Escape/close discard the session; replay starts fresh. The live editor and unsaved real drafts remain untouched behind the demo.
- All sample IDs, photos, selections and outcomes stay in memory. No sample is created through an API, added to a store/team, uploaded to private storage, published, sent, notified or written to commercial/audit history. Local image object URLs are revoked on close. Practice Team Tracking does not save its dates to the real workspace preference. A complete portal tour resumes at the next feature after finishing a fallback demo.
- Existing Vendor editor dialogs and record drawers offer Guide this window. This tours their actual headings and field labels while preserving entered values. No guide clicks a Save, Send, Publish, Accept, Delete or payment control. Window explanations do not reset saved onboarding progress or add tutorial keys.
- Buyer Help / tutorial is in Profile under Support. Steps cover Map and its radius controls, Explore and search, Projects and Work Packages, Messages/quotation requests, Orders and replay. The tour changes real tabs without tapping business controls and restores the starting tab on exit.
- After Store Activation grants full dashboard access, each authorized Vendor page automatically opens its own guide on the first visit without a saved acknowledgment. Product listings and Vehicles continue directly into their sample creation practice for editing roles; empty E-Invoices and Team Tracking open their fictional practice walkthroughs. No automatic guide opens on record editors or while another dialog is open; deferred guidance starts when that dialog closes. Leaving the page closes its automatic guide and records Skip. Each page records Finish or Skip independently per person, so the next unseen page still receives guidance. Manual feature tours retain their continuous navigation across related pages. Buyer retains its optional first-feature Show me/Dismiss prompt. All guides remain replayable from Help.
- Spotlight and copy fade in over 160 ms; the ring does not animate across unrelated targets. Motion is removed under browser/platform reduced motion. Cards keep their full available viewport height, with only long copy scrolling on short screens and large text; controls have at least 44 px targets. Native modal semantics isolate background interactions and expose close controls.
- Scrolling a tutorial target preserves horizontal scroll positions. Desktop page tutorials keep their instruction cards within the content workspace, clear of the main navigation.

## Persistence and access

`user_tutorials` stores a bounded set of acknowledgments per authenticated person, shared across devices. Vendor staff do not share the Owner's completion. No client-supplied user/organization ID is accepted. Buyer routes retain mobile bearer transport, Vendor routes retain cookie/CSRF transport, and both retain account-access checks. Each changed acknowledgment is audited, with no commercial notification. Idempotent PUT retries do not duplicate records or audit events. Tutorial acknowledgments do not change profile lock versions or store onboarding state. Vendor progress includes 23 bounded overview/page keys, while Buyer retains its six keys. Window guides remain session-only. Saving an acknowledgment never grants access to a page or changes a role. Their text is assembled from labels and purposes, never field values or private evidence.

The shared API is GET `/{tutorialPortal}/account/tutorials` and PUT `/{tutorialPortal}/account/tutorials/{tutorialKey}`. The generated TypeScript and Dart clients own serialization. No credentials or new environment variables are required. Apply `2026_11_10_120000_create_user_tutorials.php` and `2026_11_11_120000_expand_vendor_page_tutorial_keys.php` during the normal release migration step. The added migration preserves existing acknowledgments and widens the key constraint; rollback retains page acknowledgments without deleting user history.

Progress-read failures leave the application usable and expose Retry in Help. Save failures leave the tour closed, keep the acknowledgment for an explicit retry during that session, and explain that it has not been saved. If the app is closed before a successful save, the server may offer the introduction again. Intermediate step numbers are intentionally session-only; replay starts at step one.
